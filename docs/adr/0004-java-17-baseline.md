# 0004. Java 17 baseline and the protobuf 3.25 line

- Status: Accepted
- Date: 2026-11-01

Status note (2026-11): the configuration types became builder-backed classes in R2; results stay
records.

## Context

The pre-1.0 build was split: the utilities targeted Java 11 and the Micronaut module Java 17.
Micronaut 4 requires Java 17, and Java 11 is past most vendors' free public support. Records and
pattern matching for `instanceof` simplify the value types (`IndexDefinition`, `MigrationOptions`,
`QueryCompilerConfig`, ...) considerably.

Protobuf has a related constraint: code generated by protoc 4.x needs a 4.x runtime, while the
Micronaut 4 platform BOM pins protobuf-java to 3.25. Code generated by protoc 3.25 loads on 3.25+
and 4.x runtimes.

## Decision

- All modules compile with `--release 17` on a Java 17 toolchain (`.sdkmanrc`). CI also runs the
  tests on JDK 21 (`-PtestJavaVersion=21`).
- The library's protos are compiled with protoc 3.25.x and depend on protobuf-java 3.25.x, the
  oldest line whose generated code works on every runtime consumers are likely to have.

## Consequences

- Java 11 users cannot adopt v1.
- Consumers on protobuf 4.x work unchanged; consumers on the Micronaut 4 BOM are not forced off 3.25.
- Moving the baseline (to 21) or the protobuf line (to 4.x) is a breaking change for a major release
  and gets its own ADR.
- Checkstyle stays on the newest line that runs on Java 17 (12.x).
